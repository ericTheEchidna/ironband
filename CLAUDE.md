# Ironband — Godot Frontend

Godot 4.6 frontend for the Ironband game. Pure display layer — no game logic here.

## Project slug
`ironband` (Memex ID 30)

## Engine

The world/party/trigger simulation runs **in-process via GDExtension**, not as an
ibp-engine subprocess — `GlobalMap.gd` and `GameState.gd` talk to it through the
`/root/IronbandEngine` autoloaded node (GDExtension class `ib::IronbandEngine`,
source in `gdextension/src/`). The old subprocess/Protohack-over-stdio approach
(`ProtohackClient`) has been replaced; see `gdextension/src/ironband_engine.cpp`'s
"engine wiring (replaces ProtohackClient)" section in `GlobalMap.gd`.

ibp-engine (`~/source/ibp-engine`) still owns world-generation tooling
(`azgaar_to_hex.py`) and the standalone roguelike engine, but is no longer the
runtime driving the Godot frontend's world/party/trigger sim.

## World data
`worlds/cheia/` — hexbin/cellgraph binaries (`hex_grid.hexbin`, `cell_graph.bin`,
`hex_terrain.bin`, `burgs.bin`, `routes.bin`, `rivers.bin`, `cultures.bin`,
`religions.bin`, `regions.json`, `locales.json`) plus source `hex_grid.json`.
Generated by `ibp-engine/tools/azgaar_to_hex.py` from `worlds/cheia/azgaar.json`.

## Scenes
- `scenes/global/GlobalMap.tscn` — global hex world map, Camera2D pan/zoom
- `scenes/regional/RegionMap.tscn` — regional/province-level map

## Godot version
4.6, GL Compatibility renderer

## Architecture — where to edit what

**Core ownership**
- Game/render flow and UX in Godot: `project.godot`, `autoload/GameState.gd`, `scripts/global/GlobalMap.gd`, `scripts/regional/RegionMap.gd`
- In-process engine API (Godot <-> C++): `gdextension/src/ironband_engine.h`, `gdextension/src/ironband_engine.cpp`
- Sim internals (C++): `gdextension/src/core/` — `world_map.*` (terrain/hex/cellgraph data, move cost), `party_controller.*` (movement stepping), `trigger_system.*` (encounters/events/borders), `world_sim.*` (day-tick sim: patrols, market supply), `world_clock.*`, `cell_graph.*`, `hex.*`, `trade.*`
- Headless world-gen tooling and standalone engine: `ibp-engine/` (`tools/`, `worlds/`, `src/`) — no longer wired into the Godot runtime, see "Engine" above

**Common tasks**
1. Change startup scene or autoloads → `project.godot`
2. Change phase transitions (global/regional/local) → `autoload/GameState.gd`
3. Change world map loading/rendering → `scripts/global/GlobalMap.gd`
4. Add/modify engine methods exposed to GDScript → declare in `gdextension/src/ironband_engine.h`, bind + implement in `gdextension/src/ironband_engine.cpp`
5. Change world data model (hex/cellgraph loading, neighbors, move cost) → `gdextension/src/core/world_map.h`/`.cpp`; cell graph format in `gdextension/src/core/cell_graph.h`
6. Change party movement stepping (time/cost/path advancement) → `gdextension/src/core/party_controller.h`/`.cpp`; tick integration in `gdextension/src/ironband_engine.cpp`
7. Change trigger/encounter/event behavior → `gdextension/src/core/trigger_system.h`/`.cpp`
8. Run/build → `play.sh` (Godot run), `gdextension/` build for the extension, `gdextension/tests/` (doctest) for extension unit tests
